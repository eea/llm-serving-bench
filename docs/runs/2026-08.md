# Run log — August 2026 (imported)

The three runs below predate this repo. They were produced on the production
server with a single ad-hoc script (`benchmark.sh`, now replaced by
`bench/run.sh`) and copied out afterwards. Everything not listed here was not
recorded.

- 16 scenarios, 100 prompts each, legacy result format.
- Also contains `results_gpt_oss_120b_gpu0.json`: 1000 prompts, 1,152,000 tokens,
  15,831 tok/s, 13.74 req/s. No in/out lengths in the file name → excluded from
  all tables via the manifest.
- Serve flags, quantization and vLLM server version: not recorded.

## 2026-08-04 — Qwen 27B FP8 (`results/2026-08-04_qwen3.6-27b-fp8_a`)

- `model_id: qwen/qwen3.6-27b`, run stamped `20260804-083225`, `completed: 100`,
  `failed: 0` in every file.
- Serve config recovered from the docker-compose block that was commented into
  the original script → `bench/serve/qwen3.6-27b-fp8.yml`.
- This is the only run whose configuration can be audited.

## 2026-08-10 — Gemma (`results/2026-08-10_gemma_a`)

- 16 scenarios, 100 prompts each, legacy result format.
- **Model variant unknown** — no size, quantization or checkpoint id anywhere.
- All 16 files are named `results_gpt_oss_120b_*.json` (copy-paste of the
  GPT-OSS script). Values differ from the GPT-OSS run, so they are distinct
  measurements; the manifest records that this run is Gemma.

## Sweep definition (all three)

`vllm bench serve --dataset-name random --num-prompts 100` with
`--random-input-len` ∈ {128, 512, 1024, 2048} and
`--random-output-len` ∈ {128, 512, 1024, 2045}; request rate left at the default
(`inf`). Client image `vllm/vllm-openai:v0.25.0`.

## Import notes

- Raw files were copied verbatim; nothing was renamed, so the Gemma misnaming is
  preserved deliberately (history should stay auditable).
- `qwen.tgz` from the original working directory was a tarball of the Qwen run
  and was **not** imported — it duplicates `results/2026-08-04_qwen3.6-27b-fp8_a/`.
- The original hand-written README contained three claims that the data
  contradicts (a "2–4× slower than GPT-OSS" range that is actually 0.97×–4.31×,
  and a "Qwen's advantage shrinks with input size" claim that the numbers
  reverse). Those claims are not carried over; the tables are regenerated
  instead.
